## Data interface

Extraction is rooted at `<ImageNet>/train` and saves `<token_root>/<synset>/<image_stem>.pt`. DINOv2 reports images relative to `<ImageNet>`, including the `train/` prefix. `token_paths.py` resolves this difference and also accepts the original split-relative token layout and legacy index-named files.

The main format is one finite CPU float32 tensor of width 768 per image. The training dataset checks finite values and the actual student's feature width. The collate function preserves integer labels. Labels are not copied to the GPU by the student loss; category supervision has already entered the offline generative teacher.

The extraction manifest records class order, generation settings, seed and process count. Exact process shards avoid padded distributed batches writing the same sample. Atomic writes prevent partially written final token files. Reruns require matching metadata and skip existing files. Files generated by the old extractor remain readable by distillation; if resuming generation into an old directory without a manifest, use a new directory or explicitly regenerate it with `--overwrite`.

## Backbone and FSDP behavior

The public DINOv2 factory is called directly from the local package. It uses the standard hub checkpoint cache without depending on an external checkout or a repository-level `hubconf.py` in installed wheels.

`student.pretrained_weights`, when provided, points to a raw official DINOv2 backbone state dictionary and initializes all three encoder copies. The old code first loaded the public model and then attempted to load `checkpoint['model']` into the student alone. That ambiguous custom initialization behavior is removed. GPKD resume checkpoints still belong under `MODEL.WEIGHTS` / the per-rank resume mechanism.

The supplied hub-based construction ignored `student.block_chunks` and `student.drop_path_rate`. GPKD now honors those configuration values: it loads unchunked pretrained keys first, then groups the transformer blocks for FSDP. These corrections can change training behavior relative to the supplied code, even when the YAML hyperparameters agree. The default preset therefore preserves the source's effective **recipe values**, not bitwise numerical behavior or a guarantee of identical results.

The supplied DINOv2 FSDP utility expected the older `_handles`, `.params` and `_streams` internals. The unified PyTorch 2.1 stack uses `_handle.flat_param` and named stream attributes. Compatibility branches handle those interfaces and avoid trying to reshard the untouched EMA backbone after a head-only teacher forward. These are private PyTorch interfaces; the implementation requires real GPU validation before upgrading the pinned torch stack.

## Manuscript and source recipe differences

The manuscript was used as method context, not as executable instructions. Its main method, Sections 3.2–3.3, describes image-conditioned token generation and global/masked-patch distillation; Section 4.1 describes training hyperparameters. Appendix A provides pseudocode.

| Choice | Supplied effective recipe / default preset | Manuscript-oriented preset |
| --- | --- | --- |
| Generated class-state initialization | `(1-t)*eps1 + t*eps2` for linear path | `eps ~ N(0,I)` via `CLS_INIT=gaussian`, matching Eq. 8 |
| Per-GPU / total batch on 8 GPUs | 128 / 1024 from shell override | 64 / 512, per Section 4.1 |
| Epoch length | inherited fixed 1,250 updates | `ceil(dataset_size / global_batch)`; 2,503 for ImageNet-1K and batch 512 |
| Total updates | 25,000 | 50,060 at the above batch and split size |
| Head LR scaling | inherited square-root scaling | linear scaling, base `2e-4` at batch 1024 |
| Stage-2 backbone LR | explicit `2e-5`, before parameter multipliers | scaled head/base LR by omitting a separate override |
| Backbone warmup stage duration | 8 epochs from code | retained 8; manuscript does not state its duration |
| Teacher temperature | 0.04 to 0.07 over inherited 30 epochs; 20-epoch run ends before reaching 0.07 | 0.04 to 0.07 over 5 epochs; this duration is an explicit integration choice |
| Class / patch prototype heads | separate; 131,072 class, inherited 65,536 patch | shared class/patch head with 131,072 prototypes |
| Patch loss | shell turns it on with weight 1; original YAML alone set 0 | weight 1 |
| Evaluation checkpoint | EMA teacher from hardcoded update 24,999 | EMA default retained, actual student also exported |

Both presets retain the original iBOT per-image mask weighting and DINO multi-crop loss normalization. The manuscript's compact mathematical averages do not fully specify these implementation details. Teacher projection heads follow the supplied DINOv2-style EMA implementation, and the local patch backbone remains frozen. There is no claim that merely selecting the manuscript preset reproduces the reported table values.

The extraction defaults remain five ODE intervals, image noise time 0.99, linear interpolant and CFG scale 1.0. On the inherited time grid, the first four intervals use Heun's correction and the final interval uses Euler: five intervals imply nine model evaluations when Heun is enabled. Class labels still condition every model call when CFG is disabled.

REG extraction uses 256-pixel center crops and the Stable Diffusion VAE's 0.18215 latent scale. DINOv2 uses the inherited 224-pixel global crops and 98-pixel local crops. The supplied pipeline directly supports the 768-wide ViT-B/14 student. A ViT-S/14 student cannot consume these tokens without a matching-width teacher or an additional adapter; neither was present in the supplied implementation.

## Remaining validation

The code is consolidated and the local checks are documented in `VALIDATION.md`. Numerical equivalence, multi-GPU generation, FSDP forward/backward/resume, and manuscript metric reproduction have not been established on this host. Before a public model release, run the configured generator and a short GPU distillation/evaluation job, then the full recipe used for the reported checkpoints. Decide and record which initialization and training preset produced each release.
